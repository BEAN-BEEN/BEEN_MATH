# 테스트

```
node tests/run.js
```

빌드 도구가 없는 한 파일짜리 사이트라, `teacher.html` / `student.html` 안의
인라인 `<script>`를 통째로 읽어 Node의 `vm`에 올리고 함수를 직접 부른다.
브라우저를 안 띄우고도 회귀를 잡을 수 있는 가장 싼 방법.

- `syntax.js` — 두 포털과 Worker의 문법만 확인. **문법이 하나 깨지면 화면 전체가 멈추므로 이게 제일 먼저 돈다.**
- `test_*.js` — 기능별 묶음. 각 파일은 따로 돌려도 된다 (`node tests/test_omr.js`).

## 왜 이게 저장소 안에 있나

원래 임시 폴더에 두고 썼는데 파일이 조용히 지워졌다 (2026-09-06에만 15개 → 12개).
그날 이 테스트들이 실제로 두 건을 잡았다 —
분석 표의 `errs` 선언이 지워진 것과, GPT 지시서에서 `answer` 설명 줄이 덮인 것.
둘 다 화면을 열어봐야만 보이는 종류라, 안전망이 사라지면 다음 수정에서 그대로 나간다.

## 새 테스트를 더할 때

`load(파일)`이 샌드박스를 만들어 준다. `sb.__get('이름')` / `sb.__set('이름', 값)`으로
최상위 `let` 변수를 읽고 쓴다 (인라인 스크립트라 `window.이름`으로는 안 잡히는 것들이 있다).
`vm` 경계를 넘으면 `deepStrictEqual`이 실패하니 `.join(',')`으로 비교한다.
